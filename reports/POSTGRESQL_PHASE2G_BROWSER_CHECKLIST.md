# BQ Connect — authenticated browser acceptance checklist

Status: **ALL ACTIONS NOT TESTED in Phase 2G.** This is a reproducible execution procedure, not a passed test suite.

## Safe setup

1. Use only an explicitly isolated development/hosted fixture environment running the **original interface** through the guarded PostgreSQL launcher. Never run root `start.js` against imported data. Do not use real employees, destinations, keys or provider credentials.
2. An authorized operator provisions invented employee A, employee B, nonmember C, group member, moderator and administrator using the existing synthetic fixture system and normal supported registration flow. Keep disposable passwords/TOTP secrets in the fixture's private credential view, not the report, screenshots or chat. Configure only approved fixture/sandbox delivery.
3. Use a fresh browser profile on a supported desktop browser at 1280×900 and a real or emulated touch viewport at 390×844. Record browser/OS/version, fixture build and synthetic dataset identity, viewport, language, test ID, time, observed result and sanitized evidence. Mobile emulation does not certify real-device camera/video/push.
4. Open the original application's development preview. Choose English/Arabic through its existing language selector. Enter the invented employee's credentials and actual current TOTP/recovery code through the normal login UI. Do not inject bearer tokens, preload localStorage or disable authentication. Use manual takeover if the supported Agent App Testing session offers it; this session currently exposes no usable interaction runner.
5. Every row starts NOT TESTED. Change to PASS only after every listed action and assertion executes; mark BLOCKED with exact reason if setup is unavailable, FAIL for an observed defect. Do not infer results from HTTP suites. Do not collect real tokens, OTPs, mail bodies or private record screenshots.
