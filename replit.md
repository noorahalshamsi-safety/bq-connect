# BQ Connect on Replit

- Use the **Start application** workflow (also wired to Run). It runs `node development/postgres/launch.cjs` on port 5000, with a development-only alias for the imported port 4173 mapping. It runs copied original handlers/UI against an isolated PostgreSQL dataset containing invented employees and keys. It never reads imported `data/` or `backups/`. Restart the workflow after source changes; synthetic SQL data survives restarts.
- The approved Phase 2 development root is `generated-artifacts/pg-development/`, with private generated synthetic credentials. SMTP/SMS/push use explicit fixture receipts; the translation model remains disabled. See `development/postgres/README.md` and `reports/POSTGRESQL_DEVELOPMENT_INTEGRATION.md` for operation, regression coverage and limitations. The earlier empty `preview-safe.js` remains available but is not the current workflow.
- The production deployment configuration remains unchanged: VM target, `node start.js`, and App Storage synchronization. Do not publish or change production storage as part of local setup.
- Dependencies are declared in `package.json` and are already present in this workspace.
- This is an employee platform, not a disposable prototype. Keep audit work read-only against production. Do not publish, restore/import production data, rotate live credentials, migrate production database/authentication, or modify real employee records until the audit is reviewed and the user explicitly approves that work. Use only synthetic records for tests.
- Do not run `npm start` or `node start.js` in the workspace for testing: those commands load the imported data directory. See `PRODUCTION_AUDIT.md` for the initial findings and unverified areas.
- Persistence forensics/repairs must use metadata and synthetic fixtures, never production snapshots copied into development. The original `reports/P0_ACCOUNT_PERSISTENCE_FORENSICS.md` is preserved as evidence.
- Development safety repairs are documented in `reports/P0_PERSISTENCE_REPAIR.md`. Release is **NO-GO**: the installed SDK has no verified conditional-write/transaction/fenced-lease path; deployed auth writes, remote recovery/index activation and bootstrap are intentionally fenced. Do not remove these guards, initialize production manifests, or publish without separate approval and a tested durable backend/adoption plan.
